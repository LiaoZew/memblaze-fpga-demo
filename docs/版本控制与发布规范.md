# 版本控制与发布规范

统一本仓库（以及后续每个 FPGA 工程）的分支、发布与产物命名方式。

## 1. 分支策略

| 分支 | 用途 | 规则 |
|---|---|---|
| `main` | 唯一稳定分支 | 只接受 feature 合并；每次里程碑打 tag；禁止直接在其上做功能开发 |
| `feature/<名称>` | 功能/整机调试开发 | 从 `main` 切出；完成后 `--no-ff` 合并回 `main`；可选推送到远端共享 |
| `hotfix/<名称>` | 线上紧急修复 | 从 `main` 直接切出，修复后合并回 `main` 并立即升 PATCH 版本 |

标准流程（feature 分支）：

```text
git checkout -b feature/xxx origin/main   # 从最新 main 切分支
... 开发、提交 ...
git checkout main
git pull origin main                      # 更新基线
git merge --no-ff feature/xxx             # 保留合并记录
git tag -a v1.1.0 -m "..."                # 发版（见下）
git push origin main --tags
git push origin feature/xxx               # 可选：共享分支
# 合并后的 feature 分支可删除：git branch -d feature/xxx
```

## 2. Tag / 版本号规范

- 格式：**`vMAJOR.MINOR.PATCH`**（语义化版本）
  - `MAJOR`：不兼容变更（大改接口/换板/换器件）
  - `MINOR`：新增功能（新工程、新外设、新命令）
  - `PATCH`：修复（bug、烧录配置调整、文档修订）
- 必须用 **annotated tag**：`git tag -a v1.0.1 -m "说明"`（不用轻量 tag）
- 版本记录：见下“发版记录”，每次发版追加一行

## 3. 发版步骤（checklist）

1. `main` 分支工作区干净、CI/构建通过
2. `git tag -a vX.Y.Z -m "<发版说明>"`（说明里列出新增/修复要点）
3. `git push origin main --tags`
4. 在发版说明追加记录（本文件 + 根 README“当前版本”）

## 4. 多工程产物命名

每工程一套产物，避免互相覆盖，且与 `.gitignore` 白名单一致：

```
dist/<工程名>.bit   # JTAG bitstream
dist/<工程名>.ltx   # VIO 探针（MicroBlaze 工程无 ltx，正常）
dist/<工程名>.bin   # SPIx4 flash 镜像（mb_led 已并入 ELF，上电自跑）
dist/<工程名>.elf   # 软核程序（仅 MicroBlaze 工程）
```
